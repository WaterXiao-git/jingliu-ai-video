# 一键启动与等待体验

当前选择 **桌面快捷方式 + 后台轻量启动器 + 本地网页**。安装器负责首次检查和下载；日常启动直接使用已部署的 Python，无须激活虚拟环境、重新检查依赖或重新下载模型。

## 用户怎么打开

1. 首次双击根目录「打开镜流.cmd」，完成检查、安装和验证。
2. 此后双击桌面「打开镜流」。安装到其他磁盘时，快捷方式会记住实际运行目录。
3. 工作台可以先编辑剧本、导入素材。提交生成任务后，才启动视频引擎并加载权重。可选编剧服务在工作台就绪后启动，编剧模型在实际使用时加载。
4. 在生成队列查看进度，也可进入「星光等待室」玩跳跃小游戏。任务状态来自同一个真实队列；完成、失败、取消会分别提示，没有额外的模拟等待。
5. 关闭网页不会停止生成。等待当前任务完成后，双击「关闭镜流」结束后台服务。关闭会中断尚未完成的任务。

已有部署可在项目目录执行以下命令补建快捷方式。把目标目录换成自己的实际路径：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\shortcut.ps1 -Target "E:\JingliuRuntime"
```

脚本不会覆盖参数不同的同名快捷方式；会自动增加序号。移动项目代码或运行目录后，需重新创建快捷方式。删除快捷方式不会卸载模型。

需要查看控制台输出时，可运行以下命令。按 Ctrl+C 可结束由此次命令管理的服务：

```powershell
python -B deploy/launcher.py --target "E:\JingliuRuntime" --no-browser
```

启动日志在运行目录的 `launcher.log`，工作台日志在 `studio.log`。只有启动器拥有的进程树会被停止；不会按进程名称批量结束用户其他 Python、Ollama 或 ComfyUI 服务。已被其他应用占用的端口会报错，不会强行接管。

## 启动实测（2026-11-24）

机器：Windows / RTX 4060 Laptop 8GB / 16GB RAM。使用原有 ComfyUI 和 Python 环境，未新建模型副本，也未重新下载依赖。

| 测量范围 | 结果 | 说明 |
| --- | --- | --- |
| 原工作台进程到 HTTP 首页响应 | 约 2.5 秒 | 不含浏览器启动、前端初始化 |
| 原前端额外等待引擎状态 | 约 2.0 秒 | 未启动的 Ollama 探测超时会阻塞原首次渲染 |
| 新启动器进程到工作台身份接口就绪 | 3.126 / 3.074 秒 | 包含启动器开销；不含浏览器启动和模型加载 |
| 已有工作台时重复启动 | 0.323 / 0.301 秒 | 确认工作区身份后复用服务；不含浏览器启动 |
| 实际桌面快捷方式到工作台身份接口就绪 | 4.634 秒 | 包含 Windows 快捷方式、PowerShell、Python 启动；不含浏览器启动 |
| 原有视频引擎冷启动到 `/system_stats` 可访问 | 88.099 秒 | 只启动服务，尚未加载视频权重或提交生成 |

新前端将引擎探测移到首次内容渲染之后，页面不再等待这个 2 秒超时。页面内容、编辑功能和服务状态分别就绪，不显示虚假百分比。此测试没有重跑完整视频生成，不能据此推算视频出片用时；先前完整生成验收见 [验收记录](acceptance/2026-11-23/index.md)。

回归检查：25 项 Python 测试通过；Windows PowerShell 解析通过；实际桌面快捷方式启动、关闭通过。浏览器中额外把状态接口延后 5 秒，仍能先显示项目内容；等待室已检查跳跃、返回、任务完成与失败提示。浏览器中的任务状态测试使用演示数据，没有提交额外视频任务。

原始本机工作流、模型和个人项目保持使用原目录。本次测试仅增加少量启动日志和临时工作台数据。

## 等待室与资源

小游戏使用本地 Canvas 2D，最高约 30 帧，不加载外部资源，也不创建 WebGL 上下文。用户手动开始后才运行动画；关闭等待室、隐藏页面或任务结束时停止动画。最高分只保存在当前浏览器本地。任务仍按原队列顺序执行，玩游戏不会加快模型推理。

## 以后是否需要 EXE

EXE 外壳适合进一步提供独立窗口、托盘、升级与卸载体验；首次模型下载、GPU 环境准备和模型加载仍需现有部署流程。当前先保留轻量启动方案，避免增加一套桌面打包依赖。未来可复用本启动器与工作台 API 做桌面应用，无须重写生成工作流。
