# Windows EXE 启动中心（预览版）

双击 Jingliu.exe 即可打开原生启动中心。EXE 内置工作台程序与固定版本源码包，不内置数十 GB 模型，也不包含开发者的 Python、项目、配音或账户信息。无需先安装 Git、Node.js 或手动解压项目。

当前支持 Windows 10 / 11 x64，使用系统 .NET Framework 4.8 或更新的 4.x（[微软说明](https://learn.microsoft.com/dotnet/framework/install/)）。完整本地视频生成仍需满足 NVIDIA 8GB 显存、16GB 内存及 CUDA 驱动条件；EXE 不会把低配置电脑变成可运行 H3 的机器。配置不足可在“帮助 / 在线方案”选择其他平台。

## 首次使用

1. 双击 EXE。程序先查找上次部署、EXE 与当前目录附近的已部署环境，以及各固定磁盘根目录下的 `JingliuRuntime`。找到有效部署会直接打开工作台，沿用原有模型、项目和端口。
2. 新电脑会自动选择空间足够的数据盘、空闲工作台端口，并自动开始电脑检测与安装计划。新装预算为 35 GiB；空间达到 45 GiB 时默认包含本地编剧。发现附近已有 ComfyUI 时会先检查其模型和依赖兼容性，复用预算为 3 GiB，包含编剧再加 10 GiB。自动发现的 ComfyUI 不兼容时，会保留原环境，改为准备独立环境并重新检查空间；不会直接下载模型。
3. 查看显示的目录、地区、下载量和空间预算。首次缺少 Python 时，准备计划会从国内来源下载约 18 MB 官方 Python，还不会下载视频权重。
4. 点“模型许可”阅读 H3 完整原文，核对实际地区（初始为 `CN` / 中国），勾选同意后点“一键安装并打开”。目录、端口等无需手填；需要调整时展开“高级设置”，再点“重新检测”。电脑无法判断实际使用地区，也不能代替用户同意许可。
5. 安装器重新检查、校验资源，并用 4 步短镜头做功能验收，覆盖真实图生视频、本地中文配音、字幕和成片导出。正式生成仍默认 20 步。完成后自动打开浏览器，跟随新手引导制作第一条视频。

自动发现只检查已知位置，不遍历整块磁盘。自定义位置未被找到时，可在“高级设置”中选择已有部署的 runtime.json。显式传入 `--target` 时始终使用指定路径。曾准备计划的安装会记住目录，下次重新检测并续用资源；失效的旧部署路径不会阻止发现其他有效部署。端口选择后若被其他应用抢占，启动器仍会报错，不会结束那个应用。

“本地中文配音”需 Windows 已安装中文系统语音包；联网声线仍会标注“联网”。首次安装需联网下载国内资源，部署后使用本地声线可离线制作。

## 日常使用

EXE 会记住上次选择的运行目录。再次双击时，已有部署会自动打开工作台；按钮也可以手动启动。重复打开会复用已有服务。

关闭 EXE 或浏览器后，生成仍在后台继续。等待任务完成后，点击“关闭后台”或桌面“关闭镜流”结束它管理的服务。安装过程中可以用“停止当前操作”中断本次检测或安装；它只结束此次启动中心创建的进程树，已校验资源和可续传文件会保留。待操作结束后再关闭启动中心。

修改目录、地区、端口或编剧选项后，需要重新准备安装计划；旧计划不能直接复用。安装中断后，可在相同目录重新检查并继续，已校验的模型和可续传的下载会复用。

视频功能验收最多等待 1 小时，可在启动中心主动停止。安装完成或工作台打开的速度不代表视频生成速度；入门配置、首次模型初始化和显卡功耗限制可能导致较长等待。

## 文件位置与迁移

- 模型、Python 环境和项目：你选择的运行目录。已有 ComfyUI 复用原路径。
- 启动中心程序缓存：`%LOCALAPPDATA%\Jingliu\app\<版本内容编号>`，约几十 MB。
- 启动中心日志和上次目录：`%LOCALAPPDATA%\Jingliu`。
- 工作台日志：运行目录下的 launcher.log 和 studio.log。

缓存目录按 EXE 内容区分，启动时校验完整性。换一个 EXE 不会自动搬迁、删除或覆盖旧模型与个人项目。移动已有部署需同时处理 runtime.json 中的绝对路径；只移动 EXE 不影响已选择的运行目录。

## 开发者构建

先取得完整项目源码，在 Windows 的源码根目录用 Python 3.11 执行；不要在程序缓存目录中构建：

```powershell
python -B desktop/build.py
```

构建使用 Windows 自带的 C# 编译器，不下载 NuGet、Electron 或打包框架。产物包括 dist/Jingliu.exe、含 EXE 和使用说明的便携 ZIP、SHA256SUMS.txt 和 build-info.json。EXE 启动不依赖构建机器上的 Python。从源码 ZIP 构建也不强制安装 Git，无法取得 Git 版本信息时会在构建记录中标记未知。构建前请关闭正在运行的 EXE 启动中心窗口。

自动验收接口（不打开浏览器）：

```powershell
.\dist\Jingliu.exe --self-test .\dist\self-test.json
.\dist\Jingliu.exe --detect .\dist\detection.json
.\dist\Jingliu.exe --start --no-browser --target "E:\JingliuRuntime"
.\dist\Jingliu.exe --stop --target "E:\JingliuRuntime"
```

`--manage` 强制打开管理面板，跳过已部署环境的自动启动。测试可用 `--app-root` 指定独立的程序缓存目录；它只解包工作台代码，不复制模型或 Python 环境。

`--detect` 只输出自动选择结果，不安装、不解包、不启动服务；报告包含本机路径，不应作为公开附件上传。自动选择的回归检查覆盖失效路径、已有环境、中文路径、端口冲突、空间不足及安装中断续用；这些检查不等同于另一台实体电脑的完整安装验收。

[自动检测入口的本次验收记录](acceptance/2026-11-24-auto-setup.md)

自动化脚本需要等待 EXE 完成时，请使用 `Start-Process -Wait -PassThru` 并检查退出码，再读取报告文件。
